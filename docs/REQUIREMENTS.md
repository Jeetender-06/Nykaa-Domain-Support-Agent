# Capstone implementation and evidence map

Each evidence file is generated by executing the implementation under `MOCK_LLM`. Run `python scripts/verify_offline.py --evidence` after setup to recreate the evidence while external connections and DNS are blocked. Numeric loopback sockets are permitted for local Windows asyncio and API tests. No images, PDFs, videos, or presentations are needed.

| Task | Implementation | Evidence |
|---|---|---|
| 1. Dataset | `dataset.py`; 60 rows, seeded independent draws and explicit validator | `data/orders.json`, `reports/dataset_summary.json`, README design choices |
| 2. Knowledge base | `knowledge_base/*.md`; 12 topics, 4 sentences each | Authored Markdown documents and KB tests |

## Additional checks

- `reports/acceptance.json`: assertions for executed demonstrations, HTTP/WebSocket behavior, and aggregate evaluation scores.
- `reports/offline_verification.json`: test process exit status, whether evidence was regenerated inside the egress guard, and attempted outbound call count.
- `reports/environment.json`: Python/platform and installed framework versions.
- `requirements.txt`: direct dependencies pinned to the previously locked versions; the provisioned model revision is fixed in `scripts/download_model.py`.

Module paths in the table are relative to the repository root. Test and transcript paths are repository relative.
